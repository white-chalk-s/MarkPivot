# MarkPivot · 使用说明

> 面向实际使用者。产品目标见根目录 `产品定位.md`；开发规则见 [项目总则](项目总则.md)。

## 1. 适合什么场景

MarkPivot 用来把已经写好的 Word，按学校、甲方或公司模板统一成可交付文件。适合标书、咨询报告、工程文档和论文排版。文件留在本机，不会上传服务器。

## 2. 打开平台

推荐在项目根目录启动本地 HTTP 服务：

```powershell
python -m http.server 8765 --bind 127.0.0.1
```

然后访问：

```text
http://127.0.0.1:8765/MarkPivot.html
```

解压后请保持 `MarkPivot.html`、`vendor/`、`templates/` 在同一层。直接双击 HTML 可以进入基础模式，但本地 HTTP 方式更适合文件关联、图片资源和自动化验证。带着 `vendor/` 时首次打开不必联网；顶部显示「本地运行库可用（可离线）」即可开始工作。`templates/reference-template.docx` 可作为参考样例上传，页面不会自动载入。

## 3. 主流程

1. **上传文件**：首页只处理 Word（`.docx`）。可拖入文件、多选或选择文件夹。这一步已经进入当前任务。
2. **选择规范**：上传正确样例、从规范库选择，或从空白开始。三种来源都会变成同一份 Specification。上传模板后会先看到「已提取 / 未提取」摘要；未提取项不会猜测填写，可进入工作台继续改。
3. **自动识别 / 微调**：左侧是任务文件，文件卡下方显示「文档大纲」；大纲按已写入 Markdown 的标题层级排列，点击标题会跳到纸面对应位置，滚动预览时会高亮当前章节。待确认的启发式段落完成确认前不会进入大纲。中间是 Word 纸面，右侧改页面、正文、标题、表格、图片和页眉页脚。中间可切换「原文」和「当前效果」，并缩放、查看页码。较大文件解析时，工作台上方会显示进度，可取消。改规范会立刻按识别出的标题、表格和图片更新当前效果，不会改原文语义；「原文」只看未套规范的样子，随时可切回重新渲染。可选择作用到全部文件，或只作为当前文件例外。切到另一个文件再切回来，已确认的标题会保留。工作台也可上传新模板重生成初稿，或恢复进入工作时的模板值。页面、正文、标题、表格和图片 Tab 中的字段都会保留；格式参数通过常用下拉选项设置，不再自由输入。若模板或旧规范里的值不在常用选项中，会以「保留当前值」列出，避免打开后被替换。底部不再固定显示语义列表；点击预览工具栏「AI 识别」打开可关闭窗口，再展开「查看本地段落识别」修改段落类型。样式标题、列表和表格会自动标出；手工加粗标题和图题若把握不够，文件会显示「需确认」，不会偷偷改成 Markdown 标题。修改类型或确认后，才会把标题写进内部 Markdown。AI 窗口可配置 DeepSeek 和目标格式要求；点击扫描后，当前文章与要求会发送到 DeepSeek，返回的格式建议须由用户确认应用，不会改写正文。某一个文件导入失败时，其余文件仍可继续处理。
4. **导出**：点「完成调整 · 批量导出」进入导出页。1 个文件下载 DOCX；多个文件打包为 ZIP（`01 文件名.docx` …，并附带 `specification.json` 与处理记录）。导出过程显示进度，可取消；某一个文件失败不会挡住其余文件。

桌面屏幕宽度达到 1280px 时，打开 AI 识别会为窗口留出预览空间，并临时缩小纸面以避免遮挡；关闭 AI 后恢复原缩放。1279px 及以下 AI 以浮层显示，手机上可用右上角关闭按钮收起；段落识别列表在 AI 窗口内折叠查看，不固定占用预览底部。

顶部步骤条可以回到「上传文件」或「选择规范」，**不会结束任务**。一级导航的「首页」会询问是否离开，确认后结束任务，本次文件和任务规范不会保留。

规范库是一级页面，用来管理可复用 Specification，不处理具体文件。可新建、从 Word 创建、导入 JSON，并对已保存规范编辑、复制、重命名、导出 JSON 或删除。内置预设只能复制后修改。工作台里的「保存到本次任务」只留在当前任务；「保存为新规范」才会写入规范库。任务内改规范不会自动覆盖库里的条目。工作台属于某一个任务，不出现在一级导航。

原 Word / Excel / Markdown 互转能力仍作为内部引擎保留，转换无法完整保留的内容会进入报告。

### 左侧：Markdown 中枢

- **源码**：直接编辑 Markdown；内容变化会刷新右侧视图。
- **预览**：查看 Obsidian 风格的 Markdown 结果。
- **打开**：选择 `.md/.txt` 并建立当前会话的文件关联。
- **刷新**：重新读取已关联文件；如果本地编辑过，会先处理冲突。
- **保存**：把当前 Markdown 写回已关联文件。
- **自动同步**：默认关闭；开启后会定期检查关联文件是否在磁盘上发生变化。

### 右侧：结果视图

- **Word**：按当前格式规范显示 A4 纸面，可直接编辑并自动回写 Markdown。
- **Excel**：每张 Markdown 表格对应一个 Sheet；网格中的编辑会回写对应表格。表格之外的正文会以折叠摘要保留，不会被静默删除。

## 4. 常用工作流

### Markdown → Word

1. 导入 Markdown，或在左侧源码区编辑。
2. 切换右侧 Word 视图，确认标题、列表、表格、图片和分页标记。
3. 打开“样式”，选择“清爽文档”“现代报告”或“会议纪要”，也可以编辑为自定义样式。
4. 需要时在“Word 导出”中设置页眉、页脚、页码、目录和图片尺寸。
5. 点击“Word”导出，得到 `.docx`。

### Word → Markdown

1. 点击导入区的“Word”，选择 `.docx`。
2. 平台会提取正文、标题、列表、链接、图片、脚注和表格，并切换到 Word 结果视图。
3. 在左侧检查 Markdown；出现无法完全保留的内容时，打开“报告”查看 P0–P3 提示。
4. 可继续编辑 Markdown，或导出 MD/MD 包。

### Excel/CSV → Markdown → Excel

1. 点击“Excel / CSV”，选择 `.xlsx`、`.xls` 或 `.csv`。
2. 在 Excel 模式下切换 Sheet，直接编辑网格单元格。
3. 需要增加工作表时点击“＋ 新 Sheet”；它会追加到 Markdown 中枢。
4. 点击“Excel”导出 `.xlsx`，或点击“CSV”导出当前表格的 CSV。

### 批量转换

1. 打开“批量转换”，一次选择多个 `.md/.txt/.docx/.xlsx/.xls/.csv` 文件。
2. 选择目标：MD、Word 或 Excel。
3. 平台逐文件在隔离状态中转换，不会污染当前编辑区和本机草稿。
4. 有 P0 风险时先确认，再下载 ZIP 和批量报告。

## 5. 样式与 Word 导出

“样式”抽屉中的设置同时影响左侧预览、右侧 Word 预览和 DOCX 导出，但不会修改 Markdown 源码。可用能力包括：

- 内置格式预设与自定义字体、字号、颜色、行高和页面边距；
- 样式 JSON 导入/导出，便于复用自己的规范；
- 从参考 `.docx` 提取正文、标题、表头和页面边距等样式；
- 正文首行缩进开关；
- 中文强调号、表格固定列宽、封面和分页结果视图；
- 页眉、页脚、页码、可更新目录和图片尺寸上限等 Word 导出设置。

注意：格式规范是呈现层配置，不是 Markdown 内容。切换预设不应改变源码。

## 6. 表格与 WPS 注意事项

8 列以上中文表格会使用紧凑预览规则，并在 DOCX 中写入固定列宽和显式单元格边距，降低 WPS 把表头压成竖排的概率。WPS 某些版本仍可能把单元格内容渲染成前面有空隙、行距不同或与 Word 不一致的视觉效果；这属于 WPS 排版引擎差异，不代表 Markdown 中真的多了空格。

遇到表格异常时：

1. 先在左侧源码确认单元格文字本身没有空格。
2. 查看右侧预览是否正常。
3. 打开“报告”确认是否有表格降级提示。
4. 用最新导出的 DOCX 分别在 WPS 和 Word 中对照；不要为了迁就 WPS 在表格单元格前手打空格。

## 7. 转换报告怎么看

| 等级 | 含义 | 建议 |
| --- | --- | --- |
| P0 | 可能影响结果正确性的高风险问题 | 导出前必须确认，确认后再继续 |
| P1 | 已处理但可能有视觉或结构差异 | 检查对应内容和目标文件 |
| P2 | 明确的降级或暂不支持项 | 需要完整保留时回到原文件复核 |
| P3 | 信息性提示 | 通常可以继续工作 |

报告是转换结果的一部分；平台不会把已知丢失内容伪装成“完全成功”。

## 8. 支持与限制

支持 `.docx`、`.xlsx/.xls/.csv`、`.md/.txt`。不支持 `.doc`、PPT、PDF、云端协作和 Excel↔Word 直转。

目前仍需留意：

- Excel 公式按导入时的计算结果导出，不保存公式表达式；
- Markdown 不表达 Excel 的全部列宽、行高、合并和视觉元数据；
- Frontmatter 目前适合简单 key/value、列表和内联数组；
- 笔记嵌入保留引用，不读取其他 Markdown 文件或区块；
- Word 的复杂浮动布局、分节、OMML 公式和部分深层 OOXML 仍可能降级；
- 较大 Word 会分片解析并显示进度、可取消；特别大的图片可能延后预览，导出仍保留原图。Excel 超大文件尚未同等优化。

## 9. 常见问题

### 导出按钮是灰色的

查看顶部依赖状态。正常发行包会从 `vendor/` 加载运行库，不必联网。只有缺少 vendor 文件夹时才会尝试 jsDelivr，再失败则尝试 unpkg；都不可用且本机没有缓存时，编辑仍可用，但相关导出能力会禁用。

### `.doc` 导入失败

当前只支持 `.docx`。在 WPS/Word 中选择“另存为”或“保存类型”为 Word 文档 `.docx` 后再导入。

### 刷新时提示文件被修改

说明磁盘文件和当前编辑内容都发生了变化。先选择保留磁盘版本或当前版本，确认后再继续刷新/保存，避免覆盖另一份修改。

### 断网后页面还能不能用

带着 `vendor/` 或已经缓存过精确版本运行库时，可以离线继续使用对应能力。既没有 vendor 也没有缓存时，只能使用页面保留的 Markdown 降级能力。

### 如何反馈转换问题

请保留：原始文件、导出的目标文件、报告截图、浏览器/WPS 版本和最小复现步骤。不要只描述“格式不对”，最好指出具体页面、表格列或段落。
