### V4 · 表格布局与缩进修正（已完成，2026-09-03）

**现状根因**（代码定位，2026-09-03 诊断）：

1. **表格列宽策略缺失（主病）**：`tableDocx` 只写 `width:100%`，grep `gridCol/columnWidths/tcW` 零命中——Word/WPS 自动布局，中文长内容列被挤成一字一行竖排（「石家庄地铁集团」逐字折行）、短内容列空占坑（空窄列）、行高失控（用户截图 1/3）；预览端同病（无 colgroup 宽度分配）
2. **firstLine 双写**：docx 层写 `indent:{firstLine:450}`，`patchWordPackage` 后处理再补 `w:firstLineChars="200"` → 输出 `firstLineChars` + `firstLine` 双属性——OOXML 规范 chars 优先，但 WPS 对双写行为与 Word 不一致，用户实测「正文比正常的多俩个缩进」（截图 2）；列表编号缩进 `left:720/hanging:360` 偏大加重观感
3. **表格「加缩进」待复现**：单元格段落已被 `isBodyParagraphNode` 排除（`td,th` 在排除链），截图 1 的缩进感大概率是列宽错位连带视觉，修复 1 后复现确认

**需求（逐条可验收）**：

1. **表格列宽策略（导出）**：`tableDocx` 按各列最大内容显示宽度（全角=1、半角=0.5，复用 V1 字符宽算法）计算相对列宽 → 写入 `columnWidths`（`w:gridCol`）+ 每格 `tcW` + `layout: fixed`；设最小列宽保底（约 4 字符）防竖排；总宽=100% 页宽
2. **表格列宽策略（预览）**：Word 预览表格渲染同一套列宽算法（`<colgroup>` 注入），预览=导出，所见即所得
3. **firstLine 去双写**：DOCX 正文缩进只写 `w:firstLineChars="200"`（删除 firstLine 双写；docx 层不再写 firstLine，后处理改为给 pPr 注入 chars 单一属性）；WPS/Word 行为一致性以黄金断言守护
4. **列表缩进校准**：numbering 的 `left/hanging` 对齐 Word 中文默认（level0：`left:420/hanging:420` 量级，以 Word 新建文档实测值为准），消除「多俩个缩进」的列表观感
5. **截图 1 缩进复现定性**：用用户同类内容（多列中文表格）复现截图 1，修复列宽后确认「表格加缩进」是否消失；若仍有，定位并在汇报中说明
6. **踩坑记录**：表格无 gridCol 时 Word 自动布局不可控、firstLine 双写 WPS 兼容两条进项目总则

### F2 · 文档打开与刷新（已完成，2026-09-03）

**现状根因**：平台只有「导入」语义（复制进工作台，之后与磁盘文件无关）。用户核心工作流是「AI 改 md 文档 → 平台看效果」，每次都要重新导入。需求原话：**「我不想导入文件……能不能就是打开一个文档，这个 md 文档更新，平台的 md 区点刷新按钮，md 区就能自动更新」**。

**需求（逐条可验收）**：

1. **[打开] 按钮**（导入组首位）：`showOpenFilePicker` 选 .md/.txt → 授权一次（请求 readwrite 读写权限，用户拒绝则降级只读模式）→ 载入 md 区 + 内存中持有 FileSystemFileHandle；footer 显示「已关联 · 文件名」（只读关联加「只读」标注）
2. **[刷新] 按钮**（md 面板头部）：有关联时可用，`handle.getFile()` 重读磁盘更新 md 区，无需重新选文件；无关联时禁用
3. **[保存] 按钮**（md 面板头部，刷新旁）：有关联 + readwrite 权限时可用；`createWritable()` 把当前 md 写回原文件（2026-09-03 用户补充需求：「在 md 区修改内容，点击保存按钮也能同步过去」）；只读关联禁用；本地有未保存修改时按钮呈「未保存」提示态；支持 md 编辑器内 Ctrl+S 触发（preventDefault 拦截浏览器默认保存）
4. **冲突保护（双向）**：刷新侧——本地有未保存修改时弹确认防覆盖；保存侧——磁盘 lastModified 与上次读取/保存时不一致（外部已改，如 AI 刚写过）弹确认「文件已在磁盘上被修改，覆盖？」，确认后覆盖并重置基线；保存/刷新成功后同步更新基线
5. **自动同步开关**（默认关）：开启后每 2s 轮询 `getFile().lastModified`，变更自动刷新；本地有未保存修改时自动同步暂停（防打架）；权限失效自动停止并提示
6. **降级**：无 File System Access API 的浏览器——[打开] 回退普通文件选择（无关联），「刷新」「保存」按钮禁用 + tooltip 说明
7. **明确不做**：Word/Excel 关联打开（转换产物非磁盘 md，语义不通）；handle 持久化到 IndexedDB（页面重开后需重新打开，第一版不引入 IndexedDB 复杂度）；目录关联；自动上传/云同步

**验收锚点**：verify.mjs mock FileSystemFileHandle（内存实现 getFile/lastModified/createWritable）断言「打开 → 外部改文件 → 刷新 → md 区更新」「md 区修改 → 保存 → mock 文件内容更新」双向链路；刷新/保存冲突确认框各自出现；无 API 降级路径；自动同步开关生效且与本地修改不打架；Ctrl+S 触发保存；`qa:all` 全绿不回退；体积涨幅落账。

**实施与验收记录（2026-09-03）**：

- 顶栏导入组新增「打开」；支持 `showOpenFilePicker` 选择 `.md/.txt`，一次请求 `readwrite` 权限，拒绝后保留只读句柄；Markdown 页脚显示「已关联 / 只读」与文件名。
- Markdown 面板头部新增「刷新」「保存」和默认关闭的「自动同步」；刷新读取 `handle.getFile()`，保存通过 `createWritable()` 写回；编辑器 `Ctrl+S` 复用保存链路。
- 关联运行态记录读取/保存基线 `lastModified` 与文本快照；刷新前和保存前分别保护本地未保存修改、磁盘外部修改；自动同步每 2 秒轮询，遇到本地修改暂停，权限/读取失败停止并提示。
- 不支持 File System Access API 时回退现有文件选择，不保留句柄；刷新/保存禁用并通过 tooltip 说明。句柄不写入本机草稿，不做 IndexedDB、目录关联和云同步。

**验收数字**：`npm.cmd run qa:all` 为 **36 PASS / 0 FAIL / 0 SKIP**；原有 30 项全部保持通过，新增 F2 6 项；浏览器 `console.error=0`、`pageerror=0`、HTTP 错误 `0`；打开/只读关联、刷新保存双向链路、刷新保存冲突、自动同步/Ctrl+S、无 API 降级均通过。HTML `250967 B` → `266587 B`（`+15620 B / +15.3 KB / +6.2%`）；报告写入 `tools/output/f2-report.json`（`9030 B`）。

### V2 · Word 模板提取准确性 + 样式控件升级（已完成，2026-09-03）

**现状根因**（代码定位 `extractWordStyleProfile`，2026-09-03 诊断）：

1. **提取语义错位**：Word 的黑色正文**不写 `w:color`**（OOXML 默认色不落字段）→ 平台拿到空值 → 沿用 clean 预设兜底色 `#3c4039` 深灰（工房风遗色）——用户感知为「提取到莫名其妙的颜色」，实际是预设旧色冒充提取结果
2. **主题色引用未换算**：`w:color` 带 `themeColor`/`themeShade`/`themeTint` 引用时只读原始 `val`，未按 theme1.xml 色板换算——显示色 ≠ Word 实际色
3. **表头底色取样不稳**：`findWordTableHeadColor` 抓文档第一个表格首行底纹，模板示例表/主题底纹带出意外色
4. **提取不透明**：UI 只报「已映射 N 项」，每字段提取自模板哪里完全不展示，用户无从判断对错
5. **控件形态原始**：样式抽屉全部字段为自由文本 input（字体/字号/颜色手写），无常用值可选

**需求（逐条可验收）**：
