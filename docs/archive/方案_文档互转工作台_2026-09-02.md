# 文档互转工作台 · 产品规划

> 版本：v1.0 规划稿 ｜ 日期：2026-09-02 ｜ 状态：历史归档（已由当前实现与 `docs/` 现役文档承接）
> 一句话定位：**一个稳定的单文件 HTML 工具，Markdown 做中枢，左手 Excel、右手 Word，双向互转，Word 细节全覆盖，导出格式自己说了算。**

> 本文只用于回溯立项时的需求和决策。若与当前代码、QA 报告或现役文档冲突，以当前实现为准。

## 1. 产品定位

### 1.1 解决什么问题

- 手里有 Word 文档，想要干净的 Markdown 存档/发布——转换不能丢结构、丢图片、丢脚注
- 手里有 Markdown，要交一份**符合格式规范**的 Word（公文/论文/汇报各有各的格式要求）——不能每次手动调
- 手里有 Excel 表格和 Markdown 笔记之间来回搬——数字不能变字符串

### 1.2 产品原则

| 原则 | 含义 |
|------|------|
| **稳定压倒一切** | 单文件 HTML，双击即用，离线可跑（CDN 失效给出明确提示，不白屏） |
| **MD 是唯一语义层** | 所有转换都经过 Markdown，四条链路：Excel⇄MD、Word⇄MD。不做 Excel⇄Word 直转 |
| **转换可以降级，但不能撒谎** | 每一次有损转换都进转换报告（P0/P1/P2/P3），用户永远知道丢了什么 |
| **格式与语义分离** | MD 管内容，格式规范管样式。同一份 MD，换一套规范就是另一种 Word |
| **阅读体验对齐 Obsidian** | MD 区的预览渲染必须干净规范：标题层级、表格、代码块、callout 全部按 GFM 标准，不歪不扭 |

### 1.3 不做什么

- 不做 Excel⇄Word 直接互转（经 MD 中转）
- 不做 .doc 老格式（只支持 .docx），导入时明确报错提示
- 不做实时协作、云端存储、账号体系
- 不做 PPT/PDF

### 2.2 布局分区详设

#### 顶栏动作区

- **模式切换**（Excel | Word 二选一 Tab）：决定右区渲染形态
- **导入**：Excel（.xlsx/.xls/.csv）、Word（.docx）、MD（.md/.txt）三个入口
- **导出**：MD（纯文本）、MD 包（zip：md + images/ + 转换报告.txt）、Excel（.xlsx）、Word（.docx）
- **样式规范**：打开格式规范抽屉（见第 5 章）
- **转换报告**：打开报告抽屉，按钮上常驻警告数角标

#### 左区 · Markdown（源码 / 预览双态）

- **源码态**：等宽字体 textarea，带快捷插入块（H1/H2/H3/表格片段/代码块/引用/callout/任务列表）
- **预览态**：Obsidian 阅读视图级渲染（规范见 2.4）
- 双向同步：源码改动 150ms 防抖 → 右区刷新；右区 Word 预览可编辑（contenteditable）→ 回写 MD
- 同步锁：一侧编辑时锁住另一侧回写，防止回环抖动

#### 右区 · 结果视图

- **Word 模式**：A4 纸张视觉（宽 820px 纸面、页边距、阴影），按当前格式规范渲染；纸张可直接编辑，改动回写 MD
- **Excel 模式**：顶部 Sheet Tab（MD 中每个表格 = 一个 Sheet，表格前最近的一个标题 = Sheet 名），下方可编辑网格；首行即表头；网格改动回写 MD 对应表格段
- 非表格内容在 Excel 模式下的处理：网格上方以折叠条形式保留只读摘要（"本文档含 12 段正文，已折叠"），点击展开只读预览——**内容不丢，只是聚焦**

#### 状态栏

- MD 字符数 / Word 字数 / 图片资源数 / 未读警告数 / 当前模式

### 2.3 模式自动识别规则

| 导入文件 | 动作 |
|----------|------|
| .docx | 自动切 Word 模式，触发全量自检 |
| .xlsx / .xls / .csv | 自动切 Excel 模式（csv 单 Sheet，文件名作 Sheet 名） |
| .md | 保持当前模式，全量自检 |

### 2.4 MD 预览渲染规范（Obsidian 级标准）

逐项验收，渲染质量不达标 = 不合格：

| 元素 | 渲染要求 |
|------|----------|
| 标题 H1–H6 | 六级全支持，层级缩进感、字号递减、标题下锚点悬停 |
| 段落/行内 | 粗体、斜体、粗斜体、删除线、行内代码、`<u>`下划线、`<sup>/<sub>`、`==高亮==` |
| 列表 | 无序/有序/**任意深度嵌套**/任务列表 `[ ]` `[x]`（可点击勾选，回写 MD） |
| 表格 | GFM 对齐语法（`:---:` 居中生效）、长表格横向滚动、斑马纹 |
| 代码块 | 语言标签显示、等宽字体、深色代码底、横向滚动 |
| 引用 | 多段引用、引用内嵌套列表/代码 |
| Callout | `::tip / ::warn / ::info / ::desc / ::small / ::title` 扩展语法 + Obsidian 风格 `> [!tip]` 语法双支持 |
| 脚注 | `[^1]` 定义与引用，点击跳转 |
| 图片 | 资源池图片内联渲染，加载失败显示占位框+文件名 |
| 链接 | 外链新窗口打开 |
| 分隔线/分页 | `---` 分隔线；`::pagebreak` 分页标记（Word 导出为真分页符） |

## 3. 转换矩阵与核心链路

```
                ┌─────────────┐
   .xlsx/.csv   │             │   .docx
  ┌───────────► │  Markdown   │ ◄───────────┐
  │             │  （中枢）    │             │
  └───────────◄ │             │ ────────────┘
                └─────────────┘
                导出时套用「格式规范」
```

| 链路 | 方向 | 说明 |
|------|------|------|
| Excel→MD | 解析 .xlsx → 多 Sheet → MD 表格块 | 类型保留策略见 4.2 |
| MD→Excel | MD 表格块 → Sheet → .xlsx | 类型智能还原见 4.2 |
| Word→MD | 解析 .docx(OOXML) → MD | 细节清单见第 4 章，全量自检 |
| MD→Word | MD → .docx，**套用格式规范** | 细节清单见第 4 章 |

## 4. Word 细节完整清单（核心章节）

> 图例：✅ 完美转换 ｜ 🔶 有损降级（报告说明丢了什么）｜ ❌ 丢弃（报告说明为什么）
> 每一条都是验收项，逐条测试。

### 4.1 Word → MD（解析方向）

#### A. 文档结构

| # | 元素 | 策略 | 细节 |
|---|------|------|------|
| A1 | 标题样式 | ✅ | `Heading 1-6` 与中文 `标题 1-6` 双识别；`Title` 样式→ `::title`；无样式时用 `outlineLvl` 兜底 |
| A2 | 标题跳级 | 🔶 | H1→H3 跳级保留原样 + P0 报告提示确认 |
| A3 | 多级列表 | ✅ | 解析 `numbering.xml`：numFmt（decimal/bullet/roman/letter）× ilvl 嵌套 → MD 缩进列表；多级编号文本（1.1 / 1.1.1）默认不写入文本（MD 缩进已表达层级），可选开关保留编号前缀 |
| A4 | 列表段落中断 | ✅ | 列表中夹普通段落，MD 侧用缩进延续列表语境，恢复时不拆散列表 |
| A5 | 分页符 | 🔶 | `<w:br w:type="page"/>` → `::pagebreak` 标记（导出 Word 时还原真分页符） |
| A6 | 分节符 | ❌ | MD 无对应，丢弃 + P2 报告 |
| A7 | 目录 TOC | ❌ | 域代码丢弃 + P2 报告（MD 侧可由标题重新生成） |
| A8 | 页眉页脚 | ❌ | 丢弃 + P2 报告（MD 无对应；页码无意义） |
| A9 | 脚注/尾注 | ✅ | → GFM `[^n]`，定义集中文末；尾注同样处理 |
| A10 | 批注 | 🔶 | 默认转文末 `[^c1]` 式批注引用并标注「批注」前缀；可在设置中改为丢弃 |
| A11 | 修订 Track Changes | ✅ | 保留最终版本（`ins` 内容保留、`del` 内容丢弃）+ P2 报告说明存在修订 |
| A12 | 超链接 | ✅ | 外部链接 `[text](url)`；文内书签跳转降级为纯文本 + P3 报告 |
| A13 | 书签/交叉引用 | 🔶 | 提取书签内文本，引用标记丢弃 |
| A14 | 文本框/形状文字 | 🔶 | 提取纯文本按原位置插入段落 + P1 报告（位置/边框丢失） |
| A15 | SmartArt / 图表 | 🔶 | 提取替代文本；无替代文本则丢弃 + P1 报告 |
| A16 | 公式 OMML | 🔶 | 内置 OMML→LaTeX 转换器覆盖常见结构（分数/上下标/根号/积分/求和）；覆盖不了的保留可读文本 + `$...$` 包裹 + P1 报告 |
| A17 | 内容控件 sdt | ✅ | 剥壳取内容（目录控件除外，按 A7 处理） |
| A18 | 域代码（PAGE/DATE 等） | 🔶 | 取缓存显示值；无缓存值则丢弃 + P3 |
| A19 | 空段落 | ✅ | 连续空段落压缩为段落间距，不产生空 MD 段 |

#### B. 图片

| # | 元素 | 策略 | 细节 |
|---|------|------|------|
| B1 | 内联图片 | ✅ | blip→rels→media 全链提取，重命名 `images/image-001.png`，MD 引用资源池 |
| B2 | 浮动图片（anchor） | 🔶 | 转内联插入最近段落 + P2 报告（位置/环绕丢失） |
| B3 | 图片 alt | ✅ | 取 `descr`/`title`，没有则用文件名 |
| B4 | EMF/WMF 矢量图 | 🔶 | 原格式保留进 MD 包 + P1 报告（浏览器无法转 PNG） |
| B5 | 图片裁剪/滤镜等效果 | ❌ | 丢弃，只保留原图 + P3 |
| B6 | SHAPE 内图片 | 🔶 | 按 B2 同规则提取 |

#### C. 表格（重灾区，逐条定义）

| # | 场景 | 策略 | 细节 |
|---|------|------|------|
| C1 | 简单表（≤7 列、无合并、无嵌套） | ✅ | 直接 GFM 表 |
| C2 | 合并单元格（gridSpan/vMerge） | 🔶 | → HTML `<table>` 保留 colspan/rowspan + P1 报告 |
| C3 | 嵌套表格 | 🔶 | → HTML + P1 报告 |
| C4 | 单元格内列表/图片/多段落 | 🔶 | → HTML，段内用 `<br>` + P1 报告 |
| C5 | 宽表（>7 列） | 🔶 | → HTML + P1 报告（阈值可在设置调） |
| C6 | 无边框布局表 | 🔶 | 拆为普通段落流 + P3 报告 |
| C7 | 两行表头（表头合并行） | 🔶 | 首行作表头 + P2 报告 |
| C8 | 表格列宽 | ❌ | MD 无对应，丢弃 + P3 |
| C9 | 表格底纹/边框样式 | ❌ | 丢弃 + P3（导出方向由格式规范统一控制） |
| C10 | 空表格 | ❌ | 丢弃 + P3 |

#### D. 行内格式

| # | 元素 | 策略 | 细节 |
|---|------|------|------|
| D1 | 粗体/斜体/粗斜体 | ✅ | 注意 `b`/`i` 需判 `val="false"` 显式关闭 |
| D2 | 删除线/下划线 | ✅ | 下划线→ `<u>`（MD 标准外扩展，导出可还原） |
| D3 | 上下标/字符底纹高亮 | ✅ | → `<sup>/<sub>/<mark>` |
| D4 | 等宽字体 run | ✅ | 字体名匹配（Consolas/Courier/Mono/代码类中文名）→ 行内代码；段落级高占比→ 代码块 |
| D5 | **run 碎片合并** | ✅ | Word 常把一句话拆成 N 个同格式 run，必须合并后再包标记，杜绝 `**加** **粗**` 碎片化输出 |
| D6 | 特殊字符 | ✅ | `* _ \` [ ]` 等按需转义；全角字符不误伤 |

## 5. 格式规范系统（MD→Word 的灵魂）

> 这是本次规划的差异化核心：**MD 管内容，规范管样式。一套规范 = 一种交付标准。**

### 5.1 「规则从哪来」——三条途径

```
你定义格式的三个途径：
① 界面手调                    → 最直接：抽屉里点点点，右侧预览即时变
② 手调后导出 .json，以后导入   → 复用/分享/换电脑：你的规则的存档实体
③ 上传达标 Word，自动提取格式  → 零成本抄现成：连调都不用调
```

- 用户全程不接触 JSON 内容——它只是「调好的样式」的保存格式（换电脑、发同事、存档用）
- 用户手上有格式达标的现成 Word（单位模板/排好版的文件）时，走途径③直接抄

### 5.2 交互线框


## 7. 技术栈

> 原则：**无框架、无构建、无 Node**——「稳定压倒一切」的技术版本。单文件 HTML 双击即用，任何改动不需要构建环节。

| 层 | 选型 | 理由 |
|----|------|------|
| 运行形态 | 原生 JS（ES2020+）单文件 HTML | 零构建、零依赖管理，双击即用，永不腐坏 |
| MD→HTML 渲染 | **markdown-it** + 官方插件：footnote / task-lists / mark(==高亮==) / sub / sup + 自写 callout 插件（`::tip` 与 `> [!tip]` 双语法） | Obsidian 级渲染的成熟底座，手写渲染器达不到这个覆盖度 |
| Excel 读写 | **exceljs**（UMD CDN 版） | 关键决策：SheetJS 社区版不支持单元格样式（表头加粗/底纹/冻结窗格做不了），exceljs 全支持，样式要求（H4/H5）必须它 |
| CSV | **PapaParse** | 引号转义、编码、BOM 的坑全部踩完 |
| Word 解析 | JSZip + **手写 OOXML 解析**（DOMParser） | 转换报告的细粒度控制（40+ 清单逐项报告）只有手写解析做得到；mammoth 等现成库抽象层级不够且定制受限 |
| Word 生成 | **docx 8.x**（UMD CDN 版） | 原生支持 FootnoteReferenceRun（F11）、ExternalHyperlink（F12）、ImageRun（F13）、columnSpan/rowSpan 合并单元格（F15）、多级 numbering（F4）——正对四个硬伤 |
| MD 源码区 | textarea 起步；M3 视情况升级 CodeMirror 6 | 先稳后爽 |
| HTML→MD 回写 | 手写 DOM walker | 沿用现有积累，与 callout/::title 扩展语法耦合紧，用库反而要绕 |
| CDN 容灾 | jsdelivr 主源 + unpkg 备源 + 库文件存 localStorage | 任一 CDN 失效自动切换；断网可用（T2） |

**明确不用**：React/Vue（需要构建）、Tailwind（CDN 运行时编译不可靠）、TypeScript（无构建无法用）、Electron/Tauri（超出工具形态）。

## 8. 稳定性设计

| # | 项 | 方案 |
|---|-----|------|
| T1 | 依赖 | 仅 3 个 CDN 库：JSZip（docx 解包）、docx（生成）、SheetJS（Excel）；每个库加载失败时对应功能按钮置灰+提示，**不白屏** |
| T2 | 离线 | 首次成功加载后将 3 个库存 localStorage（容量允许时），断网可用 |
| T3 | 大文件 | >5MB docx / >10 万单元格 Excel 给进度提示；解析放 async 分片，避免卡死 UI |
| T4 | 数据安全 | 全程本地处理，不上传任何服务器；异常导入 try-catch 兜底，报错信息可读 |
| T5 | 编辑防丢 | MD 源码区内容变更即存 localStorage（防误关页面），重新打开提示恢复 |
| T6 | Token 纪律 | UI 颜色/字号/间距一律用 `:root` CSS 变量（真源见 `设计规范.md`），运行时代码禁止字面样式值；grep 哨兵守卫（铁律 4） |

## 10. 已确认决策

1. **格式规范入口**：JSON 导入/导出（S2/S3）管「保存与复用自己的设置」；上传参考 Word 提取样式（S5）管「从现成文档抄格式」。两者都做，S5 提前到 M2 一并实现。

3. **产品名**：定为「文档互转工作台」，不改。
4. **分工**：Claude 负责规划/设计/验收，开发实现由 Codex 执行。
