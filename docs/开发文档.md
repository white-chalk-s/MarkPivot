# MarkPivot · 文档互转工作台开发文档

> 开发日期：2026-09-24
> 当前里程碑：**M15 左侧文档大纲**。转换引擎仍为 V4.1。规范库后续（版本 / 标签 / 搜索 / 最近使用）待后续排期。用户入口见 [使用说明](使用说明.md)。
> 产品入口：`MarkPivot.html`。运行时 Excel/CSV 使用 SheetJS/XLSX 0.18.5；开发夹具使用 exceljs。未使用 PapaParse。

## 1. 开发目标

将现有的 Word → Markdown 与 Excel → Markdown 两个原型，合并为一个本地优先的文档互转工作台：

- Markdown 是唯一语义中枢；Word 和 Excel 是两种结果视图。
- Word 与 Excel 的导入、编辑、导出共享同一份 Markdown 状态。
- 转换过程保留结构，不能处理的内容必须进入转换报告，而不是静默丢失。
- 页面可以直接作为一个 HTML 文件运行；外部库不可用时，编辑区仍应可用并明确提示缺失能力。

## 4. 已实现功能

### 4.1 统一工作台

- 顶部 Word / Excel 模式切换。
- 左侧 Markdown 源码与渲染预览切换。
- 右侧 Word 视觉预览或 Excel Sheet 网格。
- 导入入口：`.docx`、`.xlsx/.xls/.csv`、`.md`。
- 导出入口：`.md`、Markdown 资源包、CSV、XLSX、DOCX。
- 本地草稿自动保存和恢复提示。
- 转换报告抽屉，按 P0/P1/P2/P3 和 PASS 展示检查结果。

### 4.2 Markdown 语义层

- 标题、段落、粗体、斜体、删除线、高亮、上下标。
- GFM 表格及列对齐信息。
- 有序/无序嵌套列表。
- GFM 脚注定义与引用。
- 外部链接。
- 任务列表。
- `::title`、`::desc`、`::tip`、`::warn`、`::info`、`::pagebreak` 等工作台指令。
- HTML 表格中的 `rowspan` / `colspan` 在 Word 导出时保留；Excel 方向在网格中保留合并区域，写回 Markdown 时按“左上角值保留、其余单元格置空”降级。

### 4.3 Word 导入与导出

Word 导入使用浏览器内的 JSZip + DOMParser 读取 DOCX OOXML，当前支持：

- 标题样式和基础正文。
- 编号列表及嵌套层级。
- 外部超链接。
- 内嵌图片进入内存资源池，并以 `images/image-###.*` 形式进入 Markdown 资源包。
- Word 原生脚注转换为 GFM 脚注。
- 基础复杂表格转换为带 `rowspan` / `colspan` 的 HTML 表格。
- 分页符转换为 `::pagebreak`。
- 对 `.doc`、批注、页眉页脚、分节、浮动图片、目录域、OMML 等不完全支持项生成报告。

Word 导出使用 docx 运行时生成可编辑 DOCX，当前支持：

- 标题、正文、代码块、提示块。
- 有序/无序嵌套列表。
- Markdown/GFM/HTML 表格及合并单元格。
- 外部超链接、内嵌图片、分页符。
- 在运行时提供 `FootnoteReferenceRun` 时，将 GFM 脚注写回原生脚注部件。

### 4.4 Excel 导入与导出

运行时沿用 SheetJS/XLSX 0.18.5（全局 `XLSX`，优先 `vendor/`）。开发夹具与 QA 回读使用 exceljs，只进 `devDependencies`。不要把两套写成同一个运行时，也不要再写 PapaParse——CSV 由 SheetJS 处理。

- 多 Sheet 映射到 Markdown 中的二级标题 + 表格。
- Excel 网格可编辑，单元格修改自动回写 Markdown 表格。
- 支持显示值 / 原始值切换。
- 日期、金额、百分比等按显示值读取，并提供智能类型恢复开关。
- 公式单元格使用计算结果写入 Markdown，并在报告中标为 P3。
- 合并单元格在网格中按原区域显示；写回 Markdown 时只保留左上角值，并在报告中标为 P2。
- 导出 XLSX 时对没有来源宽度的列自动生成列宽。
- 导入的列宽、行高和合并区域进入工作簿元数据，导出 XLSX 时写回。
- 导出 CSV 时写入 UTF-8 BOM，便于中文表格软件识别。
- 可新增 Sheet，并把新增表格追加回 Markdown。

### 4.5 M2 样式系统

- 内置“清爽文档”“现代报告”“会议纪要”三种格式预设。
- 样式字段覆盖主字体、标题、正文、行高、标题层级、正文颜色、表格、提示块和页面四边距。
- 修改字段后自动进入“自定义样式”，并实时刷新 Markdown 预览和 Word 预览。
- 样式值做白名单校验，只接受安全字体名、像素值、颜色值和数字行高，避免无效 CSS 进入页面。
- 样式保存在 `localStorage`，刷新页面后自动恢复。
- 支持导出版本化 JSON；支持从 JSON 文件导入并显示失败报告。
- 新增“从 Word 提取”：读取参考 DOCX 的 `word/styles.xml`、`word/theme/theme1.xml` 和 `word/document.xml`，映射正文默认样式、Title、Heading 1-4、主题字体/颜色、表头底色和页面边距。
- 支持沿 `basedOn` 继承链合并 Word 样式；成功后生成“参考 Word”自定义样式，未映射内容进入转换报告，不静默丢失。
- Word 导出读取当前样式变量，主字体、标题字号/颜色、正文、表头、提示块和页面边距会带入 DOCX。
- V2 已将 OOXML 缺失 `w:color` 按默认黑 `#000000` 处理，并解析 `themeColor` + `themeShade` / `themeTint`；每个提取字段保留来源徽标、明细和转换报告记录。
- V2 样式抽屉为字体、字号、颜色提供常用值下拉/色板与自定义输入，表格首行底色支持一键清除，样式 JSON 升级为 v2 并携带 `sources`。
- V2 将 Markdown `*...*` 统一渲染为非倾斜中文着重号：预览使用 `text-emphasis`，DOCX 使用 `w:em`，不再输出斜体属性。
- F3 将正文开头的 `::title` 与可选 `::desc` 组合为 `.md-cover`，提供编辑型纸面封面、居中副标题和派生分页；中部 `::title` 与仅 `::title` 边界保持可预测。
- F3 Word 导出为封面标题/说明写入 `jc=center`，标题用 `spacing before=1800` 模拟页面上部三分之一，封面后使用 `PageBreak`，并让封面区豁免首行缩进、正文恢复默认缩进。
- F3 自动分页带 `data-auto-cover-break` 标记，Word 预览回写时跳过该派生节点，保证封面格式不会污染 Markdown 源码。

### 4.6 Word 导出设置

- 新增“Word 设置”抽屉，支持配置页眉文字、页脚文字和 Word 动态页码域。
- 目录支持“不插入”“可更新目录”和“静态目录”三种策略；可更新目录使用 Word 目录域，静态目录按当前 Markdown 标题生成。
- Word 导入支持“忽略批注并报告”或“转为 Markdown 附录”两种批注策略；Markdown 没有原生批注层时，附录策略会集中保留作者与批注文本。
- 图片支持按比例限制、保留原始尺寸和固定宽高三种导出策略，并保护图片不超过页面可用宽度。
- 设置通过 `document-workbench-word-options-v1` 保存在本机；导出后页眉、页脚、目录和图片策略均写入转换报告。

### 4.7 Excel 样式与结构保真（M2.5）

- Excel 导入启用 `cellStyles`，读取单元格字体、填充、边框、对齐和数字格式，并在网格中即时呈现。
- 新增“单元格格式”抽屉，可对当前单元格设置粗体、斜体、文字/填充颜色、换行、水平/垂直对齐、数字格式和四边框线。
- 读取并写回工作表的合并区域、列宽和行高；合并区域在 Markdown 语义层仍采用“左上角值 + 空白占位”的降级规则。
- 样式与结构作为 Excel 视图元数据保存在本机草稿中，不把视觉控制字段写入 Markdown 正文，继续保持内容与布局分离。
- 工作表摘要增加样式单元格、合并区域和尺寸元数据计数；导入报告会分别标识保留项与 Markdown 降级项。

### 4.8 Obsidian Callout 与 Excel 正文聚焦（M3.1）

- Markdown 预览统一识别工作台扩展语法 `::tip` / `::warn` / `::info` / `::note` 与 Obsidian 标准语法 `> [!tip]`、`> [!warn]`、`> [!info]`、`> [!note]`、`> [!desc]`。
- 标准 Callout 支持标题、连续引用正文和类型化图标/底色；左侧预览与右侧 Word 预览共用同一套渲染结果。
- Word 预览编辑标准 Callout 后，仍按 `> [!type]` 结构回写 Markdown；工作台扩展 Callout 继续按 `::type` 回写，保持输入语法可辨识。
- Excel 模式在表格摘要区增加非表格正文的块数提示和“展开正文”入口；展开内容为只读 Markdown 预览，表格编辑不会把正文复制进网格或丢失正文。
- 正文展开状态随本机草稿保存，纯表格文档不显示多余的正文入口。

### 4.9 真实文件回归验证（M3.2）

- Markdown 夹具覆盖 H1-H6、行内格式、嵌套/任务列表、表格、代码、引用、工作台 Callout、Obsidian 标准 Callout、图片、分页符和脚注。
- DOCX 夹具由 `docx` 生成，覆盖 Title、H1-H6、编号列表、超链接、原生脚注、内嵌图片、合并表格和分页符。
- XLSX 夹具由 `exceljs` 生成，覆盖 3 个 Sheet、金额/百分比/日期/公式、换行单元格、样式、合并区域、列宽和稀疏行高。
- `verify.mjs` 对产品单文件入口、开发依赖边界、页面依赖、Markdown DOM、DOCX 包部件、XLSX 回读结构、两次回导、三张截图、无效 DOCX 错误报告和浏览器错误进行断言。
- 修复 Excel 导入的稀疏 `!rows` 元数据按 `forEach` 压缩的问题；现在按原始行索引保留空位，避免导出时行高错位。
- DOCX Title 按产品语义转换为 `::title`，普通 Heading 继续进入 Markdown 标题层级；QA 将两者分别断言，避免把 Title 误报为 H1。

### 4.10 Obsidian 语义增强（M3.1 第二阶段）

- Frontmatter 只在文档开头、且以 `---` / `...` 闭合时识别；简单 key/value、列表和内联数组会进入可视化元数据带，原始 YAML 通过 `data-frontmatter-raw` 保留，回写时不改写用户格式。
- `tags` / `tag` 字段与正文 `#标签` 统一汇总为语义标签；标题开头的 `#` 不会误识别为标签，中文标签遇到标点可正确截断。
- `[[笔记名]]`、`[[#标题|别名]]` 渲染为本地内部链接；同页标题生成稳定锚点，未解析的笔记链接仍保留引用语义。
- `![[图片路径]]` 在当前资源池命中时渲染为图片嵌入；图片缺失显示降级占位并写入 P1 报告；`![[笔记名#区块|别名]]` 显示为不可展开的笔记嵌入占位并写入 P2 报告。
- Word 预览与左侧 Markdown 预览共享同一语义渲染；Word 预览编辑后，Frontmatter、标签、内部链接和图片/笔记嵌入均按原始 Obsidian 语法回写。Frontmatter 作为元数据节点不写入 Word 正文，Excel 继续只消费表格，正文和元数据不复制进网格。

### 4.11 运行库容灾与无网启动（M3.3）

- 产品仍保持单 HTML、无构建、无运行时 npm 依赖；头部启动器维护 9 个运行库的精确版本、全局变量、jsDelivr 主 URL 和 unpkg 备 URL。
- M3.3 当时优先读取 `document-workbench-dependency-cache-v1:*`；缓存版本不匹配或源码损坏会自动丢弃并重新走网络容灾链。M10 起在缓存之前先读 `vendor/`。
- 网络加载成功且全局变量校验通过后才写入本机缓存；主源执行失败会切换备源，两个源都不可用时保留 Markdown 降级编辑区并提示缺失能力。
- 缓存命中后在应用脚本执行前恢复运行库，顶部显示“本机缓存可用（可离线）”。

### 4.12 U1 视觉范围、U2/U3 与 F1（2026-09-03）

### 4.13 V1 WPS 导出兼容与滚动主权（2026-09-03）

- 桌面视口将 `.app` 锁定为 `height:100dvh`，并沿 workspace、panel、stage 链路补齐 `min-height:0` 与内部 `overflow:auto`；`≤1080px` 通过媒体查询恢复单列整页滚动。
- 为 `.excel-stage[hidden]` 明确补充 `display:none!important`，避免组件本身的 `display:flex` 覆盖 HTML `hidden`，从而把 Excel 信息条错误显示在 Word 视图下方。
- 样式抽屉新增「正文首行缩进」开关，默认开启 2 字符；开启时只清理普通正文段落的行首全/半角空白，标题、列表、表格单元格、引用、Callout 和代码块不受影响；预览使用 `text-indent`，Word 只写 `firstLineChars=200`。
- DOCX 代码块按最长行显示宽度计算字号（全角 `1`、半角 `0.5`），导出 run 的 `ascii` / `hAnsi` / `eastAsia` 全部指定 `SimSun`，并在 OOXML 段落中写入 `wordWrap=0`；行内 code 继续使用 Consolas。
- `tools/fixtures/build.mjs` 增加 WPS 字符画与超宽混合字符样本；`tools/verify.mjs` 增加模式互斥、滚动主权、样式开关和 DOCX OOXML 断言，并落盘移动端现场截图。

## 5. 技术结构与关键决策

### 5.1 单文件优先

`MarkPivot.html` 不依赖构建工具和后端服务。头部启动器维护精确版本锁定表，并按以下顺序获取运行库：本地 `vendor/` → 本机 `localStorage` 缓存 → jsDelivr 主源 → unpkg 备源。网络返回的源码只有在执行后确认暴露了预期全局变量时才会缓存：

- JSZip：DOCX 读取与 Markdown 资源包。
- docx：DOCX 生成。
- SheetJS/XLSX：Excel/CSV 读取与生成。
- markdown-it 及插件：Markdown 渲染、脚注、任务列表、标记、上下标。

页面会显示依赖来源和缓存状态；渲染库未加载时使用降级 Markdown 渲染器，导出按钮按能力自动禁用，避免出现白屏或静默失败。缓存键包含产品缓存版本和运行库版本，运行库升级时不会误用旧源码。

### 5.2 共享状态

应用内部以 `state.md` 作为语义源，Word 预览、Excel Sheet 和 Markdown 预览都从它刷新：

```text
输入文件
   ↓
解析器 → state.md + state.assets + state.report
   ↓                 ↓
Word 视图        Excel 视图
   ↓                 ↓
编辑回写 state.md
   ↓
导出 MD / MD 包 / CSV / XLSX / DOCX
```

图片不直接写入 Markdown 文本，而是放入内存资源池；只有导出 Markdown 资源包时才写入 `images/` 目录。

Frontmatter、标签、内部链接和嵌入先被替换为无 Markdown 冲突的临时 token，再进入 markdown-it 渲染，最后在 DOM 层恢复为带 `data-*` 语义属性的可回写节点；这样既能保留 Markdown 原文，又不会把语义控制字段混入 Word/Excel 的视觉元数据。

Excel 的字体/填充/边框/对齐、列宽/行高和合并区域属于视图元数据，与 `state.md` 的语义内容分开维护；在同一次工作台会话或本机草稿恢复中可继续用于 XLSX 写回。

### 5.3 报告优先

转换报告分成两类：

- `conversion`：由具体导入/导出转换过程产生，例如公式、合并单元格、批注、分节、图片格式。
- `self`：对当前 Markdown 进行结构自检，例如标题跳级、空标题、表格列数不一致、缺失图片资源。

当前报告级别含义：

| 级别 | 含义 |
| --- | --- |
| P0 | 可能造成结构错误或明显数据风险，需要优先处理 |
| P1 | 内容可保留但有较大降级或兼容性风险 |
| P2 | 已明确降级，通常不阻断继续编辑 |
| P3 | 可继续工作但需要用户知晓，例如公式按结果导出 |
| PASS | 已通过的能力或自检项 |

### 6.3 手工启动

在项目根目录运行：

```powershell
python -m http.server 8765 --bind 127.0.0.1
```

然后打开：

```text
http://127.0.0.1:8765/MarkPivot.html
```

建议通过 HTTP 服务访问，而不是直接双击 `file:`，这样更接近真实浏览器环境，也便于后续接入本地资源与自动化测试。

M3.3 自动化回归：

```powershell
npm.cmd run fixtures
npm.cmd run qa
# 或一次执行生成夹具 + QA
npm.cmd run qa:all
```

`verify.mjs` 默认使用 `127.0.0.1:8766`，若端口被占用会自动切换临时端口，不影响用户当前在 `8765` 上打开的页面。

QA 会在测试侧回放 jsDelivr/unpkg 依赖并模拟外部网络不可用，产品 HTML 的缓存、故障转移和无库降级逻辑均在浏览器中执行；因此测试不依赖 Playwright Chromium 是否能直接访问外网。

## 7. 已知限制

- **严格 Token 清扫尚未完成**：主界面已经切换为 `设计规范.md` 的浅灰蓝/蓝紫系并移除 Google Fonts 外链；为保持历史预设和导出降级逻辑，HTML 兼容 CSS/常量中仍有白名单外字面色值 `187` 个 hex、`15` 个 rgba，后续可继续收敛到 `:root`。
- 带着 `vendor/` 首次打开不必访问 CDN。vendor 缺失且本机无缓存时才会尝试 jsDelivr / unpkg。产品字体不再请求 Google Fonts，断网时直接回退到系统字体，不影响文档转换能力。xlsx / docx 完整库不内联进 HTML。
- F2 文件关联依赖浏览器 File System Access API；不支持的浏览器只能普通导入，页面重开后需要重新「打开」文件，当前不持久化句柄、不关联目录，也不提供云同步。
- `.doc` 二进制格式不在当前支持范围内，需要先另存为 `.docx`。
- Word 导入时页眉、页脚、分节、目录域、浮动布局和 OMML 仍不能完全回写；页眉页脚与目录目前主要作为导出能力提供。
- Word 批注附录策略保留批注文本与作者，但不保留批注锚点、批注范围和 Word 原生批注气泡。
- Word 图片尺寸策略不负责重新编码 EMF/WMF 等矢量格式，复杂矢量图片仍可能需要在 Word 中进一步调整。
- Excel 公式不保存公式表达式，只保留导入时的计算结果。
- Markdown 本身不表达 Excel 合并区域、列宽、行高和视觉样式；离开工作台元数据后，单独的 Markdown 文件无法重建这些信息。
- Frontmatter 当前只解析简单 key/value、列表和内联数组；嵌套 YAML、日期/布尔类型和多行块标量仍按原始 YAML 保留，不做类型化编辑。
- 笔记嵌入当前只展示并回写引用，不读取其他 Markdown 文件或区块内容；图片嵌入需要在当前会话资源池中按路径或文件名命中。
- Excel 条件格式、主题色/indexed 色、冻结窗格、批注、数据验证和更深层的 OOXML 样式尚未完全映射；无法映射的字段仍可能需要在 Excel 中复核。
- 参考 Word 的 `themeColor` + `themeShade` / `themeTint` 基础换算已支持；复杂条件表格样式和更深层的 OOXML 版式仍未完全映射，无法映射时会在报告中提示。
- 样式预设的可命名管理和跨设备同步尚未实现。
- 超大 Word 已按档位分片解析并显示进度/取消；完整 OOXML 解析仍在主线程。Excel 大文件与 50 MB 实装二进制不在本批每次 QA 范围内。
- 批量流水线当前为浏览器内存串行处理；未加入并发限流和断点续跑。
