## 铁律（违反 = 重做）

| # | 铁律 | 违反如何被发现 |
| --- | --- | --- |
| 1 | **产品零构建**：入口永远是自包含 `MarkPivot.html`，无框架无打包、无运行时 `import`/`require`；npm 只准进 `tools/` 的 devDependencies。发行包可并列 `vendor/`（锁定版本 UMD）和 `templates/`，不得把完整 xlsx/docx 内联进 HTML | grep HTML 内 `import `/`require(` 命中即违规；`package.json` 的 `dependencies` 非空即违规 |
| 2 | **MD 是内部语义层**：Word 规范化与既有转换链仍经过 Markdown；禁止实现 Excel↔Word 直转入口。Markdown 不再作为面向用户的主产品概念 | 代码中出现不产出/不消费 MD 的格式转换函数即违规；UI 出现「Excel→Word」「Word→Excel」按钮即违规 |
| 3 | **有损必报告**：任何降级/丢弃转换（规划第 4 章标 🔶/❌ 项）必须写入转换报告；P0 未清零时导出需用户确认 | `tools/fixtures` 黄金文档转换后的报告计数与黄金值不符即违规（verify.mjs 断言） |
| 4 | **Token 纪律**：UI 颜色/字号/间距一律用 `:root` CSS 变量（见设计规范），运行时代码禁止字面样式值 | grep HTML 中 `#[0-9a-fA-F]{3,8}` 色值与 `px` 字面样式，白名单（Token 定义区）外命中 >0 即违规 |
| 5 | **格式与语义分离**：切换格式规范/预设只影响预览渲染与导出，永不改动 MD 源码 | verify.mjs 断言：切换预设前后 MD 源码 diff ≠ 0 即违规 |
| 6 | **AI 只提格式建议**：仅用户主动调用时把当前文章和格式要求发给 DeepSeek；API Key 默认只存当前会话；AI 结果经字段白名单校验并由用户确认后写入 Specification，绝不改写正文 | 静态检查必须确认请求由按钮触发、提示明确、正文不在 AI 应用路径内写入 |
| 7 | **规范栏不自由录入**：页面、正文、标题、表格、图片的字段都保留，但格式值使用常用选项；模板或旧规范中的非标准值作为“保留当前值”保真展示，不静默覆盖 | 工作台与规范库编辑器的 Specification 控件均不得出现自由文本或数字输入 |

## 技术栈与命令

- **产品**：原生 JS 单文件 `MarkPivot.html`；运行时库锁定版本副本在 `vendor/`：markdown-it（+footnote/task-lists/mark/sub/sup 插件）、JSZip、docx 8.5.0、SheetJS/XLSX 0.18.5。加载顺序：vendor → localStorage 缓存 → jsDelivr → unpkg。CSV 由 SheetJS 处理，**未使用 PapaParse**。开发夹具与 QA 使用 `exceljs`（只进 `devDependencies`），不要把 SheetJS 运行时和 exceljs 开发依赖写成同一套。刷新副本：`npm.cmd run vendor`。
- **验证**（M0 批交付后生效）：`node tools/verify.mjs` —— console error 数 + 三视图截图基线 diff + 黄金文档转换断言 + HTML 体积
- **fixtures**：`node tools/fixtures/build.mjs` —— 重新生成黄金测试文档（sample.docx/.xlsx/.md）

## 踩坑记录（随开发追加，先记现象后补根因）

- **HTML 复杂表格导出 Word 变纯文本**（2026-09-02，继承自原型 v2.0）：原型对 `<table>` HTML 块按等宽文本段落输出。纪律：MD→Word 前必须解析 HTML 表格为 docx Table（含 colspan/rowspan），黄金用例覆盖。
- **MD 图片导出 Word 直接丢失**（2026-09-02，继承自原型 v2.0）：原型的行内解析不处理 `![]()` 语法。纪律：导出管线必须有图片资源池嵌回断言。
- **SheetJS 社区版不支持单元格样式**（2026-09-02，选型时确认）：表头加粗/底纹/冻结窗格做不了。纪律：Excel 读写一律 exceljs，不引入 xlsx 库。
- **Word 同格式 run 碎片化**（2026-09-02，原型已暴露）：Word 把一句话拆成 N 个 run，直接逐 run 包标记会输出 `**加** **粗**` 碎片。纪律：相邻同格式 run 必须合并后再包标记。
- **`min-height` 会夺走滚动主权**（2026-09-03，V1）：`.app` 只设 `min-height:100dvh` 时，长文档会把整个工作台撑高，面板的 `overflow:auto` 失效。纪律：桌面工作台用 `height:100dvh` + `min-height:0` 锁住根视口，移动端再通过媒体查询释放为整页滚动。
- **Consolas 不能承担中英文字符画对齐**（2026-09-03，V1）：代码块只设置 `font:'Consolas'` 时，WPS 对中文回退字体，中英宽度比例和字符画边框会漂移。纪律：代码块导出显式设置 `ascii` / `hAnsi` / `eastAsia` 三通道为 `SimSun`，并按最长行显示宽度自适应字号、关闭段落折行；行内 code 仍可用 Consolas。
- **手打全角空格是假首行缩进**（2026-09-03，V1）：把 U+3000 当缩进会造成有的段落缩进、有的段落不缩进，导出还会叠加双重缩进。纪律：首行缩进作为样式开关统一控制；开启时仅清理正文段落行首全/半角空白，关闭时不改源文档空白；标题、列表、表格、引用和代码块排除。
- **Word 黑色常省略 `w:color`**（2026-09-03，V2）：OOXML 缺失颜色字段不代表“没有颜色”，而是沿用默认黑；提取时必须映射为 `#000000`，不能回退到旧预设深灰并误报为模板颜色。
- **主题色不能直接读原始 `w:val`**（2026-09-03，V2）：遇到 `themeColor` 时必须读取 `word/theme/theme1.xml`，再按 `themeShade` / `themeTint` 换算实际色值；来源和换算明细要进入样式状态与转换报告。
- **中文伪斜体改为语义着重号**（2026-09-03，V2）：本产品的 Markdown `*...*` 统一使用非倾斜 `text-emphasis` 预览和 DOCX `w:em val="dot"` 导出，不通过 `w:i` / `italics` 制造斜体；格式变化不得改写 Markdown 源码。
- **封面是开头语义，不是普通标题变体**（2026-09-03，F3）：只有正文开头的 `::title` 才能触发封面，允许一个空行后接 `::desc`；中部 `::title` 必须保持普通标题。自动分页属于派生视图节点，回写 Markdown 时不能把它写回源文件。
- **封面区必须豁免正文排版规则**（2026-09-03，F3）：封面标题/说明居中并使用独立间距，不能继承正文 `firstLineChars`；封面后的普通正文仍需恢复原有首行缩进。
- **表格列宽必须显式落地**（2026-09-03，V4）：Markdown/Word 预览与 DOCX 导出不能依赖浏览器或 Word/WPS 自动布局；必须按内容宽度写入预览 `colgroup`、DOCX `gridCol/tcW` 和 `fixed` 布局，并保留最小列宽，避免中文长词逐字竖排。
- **WPS 宽表的默认边距会吞掉可用列宽**（2026-09-03，V4.1）：8 列及以上的中文表格必须采用紧凑预览规则，并在 DOCX 的表级和单元格级显式写入 `tblCellMar/tcMar`；单元格段后距归零，避免表头逐字换行或竖排。
- **DOCX 正文首行缩进只保留一种 OOXML 属性**（2026-09-03，V4）：`firstLine` 与 `firstLineChars` 双写会造成 WPS/Word 行为差异；正文只输出 `w:firstLineChars="200"`，列表、标题、表格、引用和代码块排除首行缩进。
- **模板提取必须直接产出 Specification**（2026-09-23，M4）：禁止把参考 Word 先灌进 CSS 再 `specFromCss()` 往返；那样会把「沿用默认」标成已提取。缺少 `pgSz` / 页眉页脚时保持未提取；文档里观测到的图片尺寸不是图片约束，不得写入 `image.maxWidth/maxHeight`。
- **低置信度语义不得静默改写 Markdown**（2026-09-23，M5）：Heading Style / 表格 / 列表 / 图片可直接识别；手工格式标题只能启发式评分且置信度封顶，必须用户确认后才把 `#` 标题写进 MD。识别器不得作为导入器的唯一改写路径。
- **切文件重导入不得覆盖已确认 Markdown**（2026-09-23，M6）：切文件是为重建图片资源才重跑 Word 导入；必须先记住当前文件 MD，导入完成后再恢复。导入过程中的草稿保存不能把刚解析的原文写回任务文件。原文预览只套空白规范且 `previewOnly`，不得改任务 Specification 与导出选项。
- **规则引擎不得污染 Markdown**（2026-09-23，M7）：Semantic Node 只决定预览与导出样式。启发式标题可在当前效果显示为 H1–H3，但未确认前不得写入 `#`。导出提升标题标签只允许发生在临时 holder，不能改写纸面 DOM，以免回写 Markdown。
- **任务批量导出不得走 F1 抽屉**（2026-09-23，M8）：产品任务导出与 `?qa=` 的旁路批量转换是两条路。任务导出必须在沙箱里复用 `importWordEngine` + `buildWordBlob`，恢复已确认 Markdown，失败隔离；禁止 `addBatchFiles(task.files)` 或 `clearAssets` 打到工作台当前文件。
- **完整 Word 解析不能搬进 Worker**（2026-09-23，M9）：`DOMParser`、样式解析和纸面渲染绑在主线程。大文件靠分片 `forEachBodyChunk` + `setTimeout(0)` 让出 UI；Blob Worker 只处理 ping 与预览缩图。`?qa=` 不得截断预览。一个文件失败只能标该文件，不能结束整个 Task。
- **完整运行库不内联进 HTML**（2026-09-23，M10）：xlsx.full.min 与 docx UMD 合计超过 1.5 MB，内联会撑破单文件体积。纪律：发行包用 `vendor/` 锁定 UMD；HTML 只做版本表与加载器。`file://` 不能 fetch 本地脚本，必须用 script 标签。CDN 只在 vendor 缺失时作后备。
- **任务微调不得自动覆盖规范库**（2026-09-23，M11）：规范库是资产，不是当前任务的另一面。改正文/标题只写 Task 或 file override。只有「保存为新规范」或规范库页的保存才写入 `markpivot-spec-library-v1`。编辑库内规范不得改 `task.specification`。
